# House web research room implementation plan

**Goal:** `house web` starts a local browser control surface for one Main and its four reusable room agents, using the existing Codex login and research records.

**Approved design:** The user selected CLI startup with browser operation, following the interactive research-room preview. Keep Main, Literature, Work, Output and Discussion; all new user work goes through Main. Status and progress must come from actual events. The browser is not a second agent runtime and must never invent research completion.

**Architecture:** A Python standard-library loopback HTTP server owns a Codex `app-server --listen stdio://` child. A bounded JSON-RPC client streams native events and approval/input requests. A controller maps native thread IDs to the fixed rooms and feeds a self-contained HTML/CSS/JavaScript interface. Existing invocation-scoped hooks, role configs, session checkpoints and project pins remain in force. The old foreground CLI path stays available.

**Tech stack:** Python 3.9 standard library, unittest, native Codex 0.154.0 generated protocol schema, browser JavaScript and SVG. No framework installation, database service, cloud deployment or global Codex config changes.

## HTTP contract

The launcher prints an unguessable fragment URL on `127.0.0.1`. The browser reads the fragment into memory and sends `Authorization: Bearer <token>` to API routes; tokens never go into query strings, cookies or logs. Validate exact Host and same-origin Origin; do not enable CORS. Use fixed static asset paths and bounded JSON bodies.

`GET /api/state` returns `{project, connected, ready, error, thread_id, goal, rooms, requests, queue, session}`. `rooms` is an array of `{id, label, status, task, agent_id, last_activity, events, messages, files}`. Statuses: `unassigned`, `idle`, `working`, `waiting`, `failed`, `unknown`. Events contain `{at,text}`; messages `{id,role,text}`; files `{path,label}`. `requests` contains `{id,method,room,params}` for exact native server requests. `session` contains the saved context observation and automatic-compaction policy state when available; missing measurements stay null.

`POST /api/message` accepts `{room,text}` and returns an acknowledged queued request; always route through Main. `POST /api/respond` accepts `{id,decision}` for command/file approval or `{id,answers}` for native clarification questions. Native request IDs must already exist locally; validate decisions and answer shapes. `GET /api/file?path=<relative>` returns `{path,text}` for bounded allowed project text files, refusing traversal, symlinks, hidden config and binary/raw data.

## Verification commands

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=skill/scripts python3 -m unittest discover -s tests -q
git diff --check
house web --dry-run --json --project /path/to/research
```

Browser refreshes only read state and never start a model turn. Closing a browser tab does not stop Codex. The CLI owns server lifetime; explicit terminal shutdown closes this connection without declaring the research complete. Unknown runtime state and protocol failures are surfaced; accepted input and completed research are distinct.
