# House v0.1 검증 기록

검증일: 2026-10-08. Python 3.9.6, macOS, codex-cli 0.154.0.

## 확인한 동작

- 비어 있지 않은 프로젝트 초기화, 재진입·중첩 방에서 재개, 기존 문서·AGENTS·버전 잠금 보존.
- 경로 충돌·symlink·동시 초기화 처리, 원자적 JSON 기록과 방 실행 잠금.
- 공용 방 지침과 양식의 해시 검증, 엔진에 새 양식이 생겨도 기존 릴리스 사용 가능.
- 실제 터미널 PTY의 메뉴 2번 → literature 작업 경로 → 테스트 Codex 프로세스 실행 → 종료 기록.
- 설치된 실제 Codex의 읽기 전용 임시 Main 확인: `HOUSE_SMOKE_OK`, release `0.1.0`, 입력한 연구 목표 반환.
- 실제 GitHub 공개 탐색: 문헌 검색 후보 3개와 Trending 후보 3개, 오류 없음. 검토 전 후보로 기록하며 설치하지 않음.
- GitHub 통신 fixture로 revision 고정, stage·검토·증거 스냅샷·apply·pin·rollback 전체 수명주기 검증.
- 후보/스킬/검토 내용 변경 감지, 기존 프로젝트 잠금 보존, 현재 릴리스가 손상돼도 유효한 이전 릴리스로 복구.
- 설치 충돌 보존, 반복 설치, CLI·스킬 심볼릭 링크, 주간 작업 argv와 경로 검증.
- 주간 알림: 변경이 없으면 조용함, 오류 응답을 실패 알림으로 기록, OS 제출 실패 시 재시도.
- skill-creator의 `quick_validate.py`: `Skill is valid!`.

## 스킬 사용 시나리오

격리된 동일한 연구 시작 요청을 스킬 없이 수행했을 때는 개별 `Main/README.md`만 생겼습니다. House 스킬을 적용한 시나리오에서는 다섯 방을 생성하고 목표·설계·인계를 기록했습니다. 기존 사용자 메모의 SHA-256은 동일했습니다. 구현·학습·인용·결과·사용자 동의를 만들어내지 않았습니다.

초기 시나리오에서 `rationale.md`/`why.md`의 불일치를 발견했고, 최종 코드에서는 `why.md`로 통일했습니다. 이후 핵심 테스트가 실제 파일 존재를 검증합니다.

## 검토에서 수정한 사항

- 현재 채팅 context가 프로젝트 상위 폴더에서도 House를 찾도록 수정.
- 실행 로그 디렉터리 생성과 변경된 공용 지침의 무결성 검사.
- 신규 엔진 양식이 이전 프로젝트의 버전 고정이나 사용자 경로와 충돌하지 않도록 수정.
- 설치 기본 공용 경로 일치, quoted tilde 정규화, 사용자 지정 HOME의 환경 설정 요구 명시.
- 반환된 검색 오류도 주간 알림으로 기록.
- 중단된 스킬 복사가 최종 저장소를 오염시키지 않도록 원자적 게시.
- tar 메타데이터를 포함한 전체 압축 해제 크기 제한.

## 범위

실제 연구 모델 학습이나 외부 스킬 채택은 수행하지 않았습니다. 자동 테스트의 대표 검토 증거는 테스트 fixture이며 실제 후보의 품질 평가로 사용하지 않습니다. 화면 알림은 OS에 제출한 상태와 사용자가 실제로 본 상태를 구분합니다. 운영 기록·다운로드·연구 데이터는 Git 제외 대상입니다.

재검증: `PYTHONPATH=skill/scripts python3 -m unittest discover -s tests -v`

실제 배포 확인 중 macOS launchd의 Desktop 접근 차단을 재현했습니다. 공용 데이터를 Application Support로 분리하고, 주간 실행용 Python 파일을 해시별 스냅샷으로 이 위치에 등록하도록 수정했습니다. GitHub CI의 Codex 미설치 환경도 테스트 실행 파일 fixture로 처리했습니다.

## 최종 배포 확인

- 로컬 자동 테스트 60개 통과.
- GitHub Actions의 macOS/Linux × Python 3.9/3.12 네 조합 모두 통과: https://github.com/ISIF-3/house/actions/runs/37746103062
- Desktop/house 저장소, house 명령과 Codex 스킬 연결 확인. 원격은 비공개 ISIF-3/house, 기본 브랜치는 main.
- 실제 launchd 작업에서 오류 없는 첫 탐색 완료: 후보 30개(방별 검색 25개, Trending 5개). 새 후보 25건을 하나의 macOS 알림으로 제출. 실제 배너 열람 여부는 확인하지 않음.
- 공용 데이터 경로는 Application Support, Desktop에 shared/workshop/runtime 바로가기 확인. 초기 Desktop 접근 실패 로그는 과거 기록으로 보존.
- 설치된 명령의 새 임시 프로젝트가 올바른 공용 경로를 잠그는 것까지 확인. 기존 연구 프로젝트 변경 없음.

## 0.2.0 검증 · 2026-10-12

- 자동 테스트 78개 통과(기존 60개 + 기록 관리 18개). 0.1.0 템플릿을 fixture로 고정해 실제 이전 버전 프로젝트를 만든 뒤 마이그레이션을 검증한다.
- 마이그레이션: 사용자 편집 보존, 0.1.0 초기 문구 한 줄만 교체, `previous/` 백업, 고정 버전 history, 재실행 시 변경 없음, `--dry-run` 무변경.
- offload: 상대 링크로 기존 경로 유지, 목록·크기 해시, 이미 옮긴 경로·기록 포함 폴더·house/ 내부 대상·기존 대상 거부, 다른 디스크 복사 검증 실패 시 원본 유지와 임시본 정리, 최근 변경 폴더 거부.
- git: house/ 자체 저장소 생성과 기록만 커밋, npz 제외, 원본 규모 거부, 상위 저장소에서 `literature/` ignore 규칙 아래 방 폴더 재포함과 다른 staged 변경 유지. 사용자 전역 git 설정과 분리해 실행.
- 실제 프로젝트 사본(공용 홈 포함 복사, 원본 무변경): 이미 문서를 새로 쓴 프로젝트는 House 파일 8개 교체와 `.gitignore` 생성만 수행. 큰 파일 4개(165MB)를 옮긴 뒤 house/ 183MB → 18.5MB, `house track` 커밋 158개 파일, 점검 권장 작업 없음.
- 템플릿 위에 덧붙여 쓴 프로젝트 사본: 문서 11개의 초기 문구를 각각 한 줄만 교체, 템플릿 해명 줄 8개와 71,479자 handoff를 남은 작업으로 보고, 상위 `literature/` ignore 해소 확인.
- 실제 40GB 프로젝트의 읽기 전용 `house check` 1.9초(파일 143,369개), `offload --suggested --dry-run`은 후보 29개(34.6GiB)를 계획하고 13분 전에 바뀐 실행 출력 1개를 제외. 아무 파일도 만들거나 옮기지 않음.

## 0.4.0 웹 운영 검증 · 2026-10-19

- 전체 자동 테스트 175개 통과. JSON-RPC 16개, 웹 제어기 14개, HTTP 17개를 포함하며 CLI 테스트는 18개다. `git diff --check`와 JavaScript 구문 검사도 통과했다.
- 실제 Codex CLI 0.154.0과 기존 로그인으로 임시 연구 프로젝트를 사용했다. 일곱 House 훅의 활성 여부·명령·해시를 확인하고, 해당 실행에 대한 명시적 신뢰 허용 후 Main 세션과 작업 폴더를 만들었다. 짧은 실제 모델 응답이 완료됐고 전역 Codex 설정 파일의 SHA-256은 동일했다.
- 실제 Main이 Work 담당 한 명을 생성한 뒤, 후속 지시에서 같은 native agent ID를 재사용하고 두 응답을 완료했다. 자식 에이전트의 이벤트가 해당 방에 연결되고 작업 후 idle로 돌아오는 것을 확인했다.
- Chrome에서 실제 로컬 서버에 연결해 훅 신뢰 검토 → Main 지시 전송 → 실제 모델 응답 → 프로젝트 텍스트 파일 열람 → 인증을 유지한 새로고침을 확인했다. 브라우저 JavaScript 오류는 없었다.
- 별도 테스트 HTTP API를 사용하는 Chrome 검사에서는 방 이동·키보드 조작, 모바일 390px 화면, 안전한 텍스트 출력, 전송 실패 시 초안 보존을 확인했다. 실제 모델을 호출한 브라우저 검증과 구분한다.
- HTTP 검사는 Host·Origin·토큰, 요청 크기·JSON 형식, 파일 경로·symlink·크기 제한을 확인한다. 제어기 검사는 신뢰 검토 전 작업 거부, 중복 승인 방지, 빠른 완료 이벤트 보존, 불확실한 전달의 자동 재전송 방지, 기록에서 담당자 ID 복원을 포함한다.
- 검증용 프로젝트를 사용했으며 기존 연구 파일과 고정 릴리스를 바꾸지 않았다. 대규모·장기 연구 및 반복 압축의 관측 완전성은 검증하지 않았다. 같은 채팅을 CLI와 웹에서 동시에 조작하는 기능은 제공하지 않는다.

### 화면 재배치와 모델 선택 · 2026-10-19

- 전체 자동 테스트 186개 통과(23.349초). 웹 제어기·HTTP 테스트 42개에서 모델 목록의 페이지 처리·오류·입력 검증, Main 설정 관측, 모델 선택만으로 턴이 시작되지 않음, 대기열의 요청별 모델 보존, 기존 모델 필드가 없는 기록의 호환을 확인했다. 모델 API는 기존 로컬 인증을 사용하며 모델 키가 빠진 요청은 400으로 거절한다.
- Chrome와 테스트 HTTP API로 중앙의 작업 요청 → 연구실 → 선택한 방의 결과 대화 → 승인 순서, 목표·Main ID 표시 제거, 방별 대화 전환, 모델 저장 중 전송 차단, 요청 전송 중 모델 변경 차단, 선택 실패 시 복구·초안 보존, 파일 열람·승인·질문·인증 새로고침을 확인했다. 모바일 390px에서 가로 넘침과 브라우저 JavaScript 오류가 없었다.
- 현재 설치된 Codex 0.163.0의 스키마와 native `model/list`를 확인했다. 별도 임시 프로젝트에서 실제 일곱 모델을 읽고 Main 설정 `gpt-6.1-sol`에서 `gpt-6-luna`를 선택했다. 선택만으로 턴은 시작되지 않았으며, 이후 제출한 짧은 요청의 응답 완료와 native 설정 관측 갱신을 확인했다. 전역 Codex 설정 파일의 SHA-256은 동일했다.
- 기존 연구 세션에는 접속하거나 종료 명령을 보내지 않았다. 이미 실행 중인 서버는 backend 변경을 반영하려면 재시작해야 한다. 장기 운영과 모든 모델·추론 강도 조합은 검증하지 않았다.

### 추론 강도와 Fast 모드 · 2026-10-19

- 전체 자동 테스트 207개 통과(25.573초), 웹 제어기·HTTP 테스트 63개. native 지원·기본값의 형식과 한도, 모델·추론·Fast의 원자적 검증, 요청별 설정 저장, 이전 queue 호환, 자식 알림 격리, 명시적 표준의 null 전송을 확인했다. 목록 조회 실패나 지원 metadata 누락 시 같은 Main 모델의 이미 관측된 설정은 보존하며, 다른 모델은 그 모델의 기본값을 사용한다.
- Chrome과 테스트 HTTP API에서 실제 지원 추론 단계만 노출, 미지원 모델로 전환 시 강도·Fast 자동 복귀, 실패 시 세 선택 복구·초안 보존, 저장·전송 중 세 선택기 차단을 확인했다. 기존 승인·질문·파일 열람·인증 새로고침과 모바일 390px 검사를 통과했고 JavaScript 오류가 없었다.
- 임시 House 프로젝트와 실제 Codex 0.163.0으로 `gpt-6-luna`의 low + Fast(`priority`) 요청 후 medium + 표준(`default`) 요청을 완료했다. 두 차례 모두 Main 관측값이 일치했으며, native `serviceTier: null`이 Fast를 해제하는 것을 확인했다. 전역 Codex 설정 파일의 SHA-256은 동일했다.
- 기존 연구 세션에 접속·중단하지 않았다. Fast의 실제 속도 배수나 추론 품질 비교, 모든 모델·추론 단계 조합, 장기간 운영은 검증하지 않았다. 사용량 증가는 [공식 속도 문서](https://learn.chatgpt.com/docs/agent-configuration/speed)를 연결해 안내한다.
